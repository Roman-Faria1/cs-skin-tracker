# v0.3 Milestone Confirmation

Confirmed October 21, 2026 against merged main `f67650a` (PRs #4-#7).
This records engineering milestone completion, not a published release. No release tag
was created and workspace package versions remain `0.0.0`.

## Release Gates

- [x] Alerts evaluate stored snapshots without requesting provider data. Unit and service
      tests cover price, percent-change, spread, stale-data rules, and failed/skipped refreshes.
- [x] Portfolio valuation uses existing cached quotes without additional CS2Cap requests.
      Tests cover lot persistence, exact totals, unknown costs, partial coverage, freshness,
      provider filters, and concurrent capacity protection.
- [x] Alert history is persisted and auditable. Repository tests cover immutable evidence,
      one event per generation, lifecycle changes, concurrent evaluation, pagination, and
      retained history after source rules/items are deleted.

All v0.3 feature TODOs in ROADMAP.md are complete, including the cache-only market overview.
The merged baseline has 185 passing unit/API/integration tests (30 Postgres tests and
one Redis scheduler test). Its 38 existing desktop/mobile browser regressions also pass
during the v0.4 auth work; typecheck, lint, formatting, and production build are verified
with that work. Tests use fixtures and the isolated `_test` database; no provider quota
was spent on milestone confirmation.

## Known Limits

- This remains a single-owner dataset, not a multi-user product.
- In-app alert history is the first notification channel. External notifications and an
  independent stale-alert timer are deferred; cached checks run after refresh or explicitly.
- Collection is opt-in and remains disabled. Missing fresh same-provider history is labeled
  unavailable, not flat. Do not spend quota solely to fill movement charts.
- Values are USD listing asks, not recent sale prices, fee-adjusted proceeds, or bids.
  Steam wallet asks are included when all markets are selected.
- Live Supabase auth, hosting, backup/restore, monitoring, and deployed smoke checks belong
  to v0.4 and are not release gates satisfied by these local tests.

## Next Phase

Start v0.4 with the private owner auth gate for both web and API, then verify it against
the configured Supabase project before any hosted access. Deployment, observability,
backups, and hosted smoke checks follow. Agree on release tagging separately; do not
silently bump every workspace package to represent a roadmap milestone.
